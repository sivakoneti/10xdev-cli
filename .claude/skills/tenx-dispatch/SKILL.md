# Subagent Ticket Dispatch

You are the supervisor agent. When tackling complex epics or multiple spec
tickets, delegating tickets to isolated subagents keeps your context window
clean (~90% token savings) and eliminates reasoning degradation.

## When to delegate

- **Independent tickets:** The ticket has clear inputs and outputs and can be
  developed/tested without continuous dialogue with the supervisor.
- **Heavy context risk:** The ticket involves reading many large files, running
  verbose test suites, or exploring dependencies that would fill the main
  context.
- **Parallel work:** Multiple tickets across different modules can run
  concurrently in separate git worktrees without collision.

## The Dispatch Protocol

1. **Generate the Brief:**
   Run `tenx ticket-brief <SPEC-ID> <TICKET-ID>`.
   Review the scoped context (ticket description, requirements, conventions,
   and test commands).

2. **Dispatch Worker:**
   - **CLI / Process Mode (Codex, Prime Agent, Pi, Grok, Claude):**
     Run `tenx dispatch <SPEC-ID> <TICKET-ID> --agent <name>`.
     This automatically creates a clean git worktree at
     `.tenx/worktrees/<TICKET-ID>`, writes `TICKET_BRIEF.md`, and runs the
     worker in headless mode.
   - **In-Band Tool Mode (DSH Web, Pi with pi-subagents):**
     Call your native delegation tool (e.g. `@deepseek-ai/dsh-tool-subagent` or
     `Agent({ isolation: "worktree" })`) passing the brief generated by
     `tenx ticket-brief`.

3. **Supervise and Reconcile:**
   - When the worker finishes, examine its structured receipt:
     - Return code / completion status.
     - Worktree branch name (e.g. `tenx/<TICKET-ID>`).
     - Validation & test evidence.
   - If tests failed or the worker is blocked, inspect its diff or logs.

4. **Verify & Land (Landing Discipline):**
   - Run `git diff main..tenx/<TICKET-ID>` to review the changes.
   - Verify `tenx validate` passes with 0 errors.
   - Fast-forward or merge the branch into main.
   - Update ticket status: `tenx ticket <SPEC-ID> <TICKET-ID> done`.
   - Log evidence: `tenx log "Implemented <TICKET-ID>" --ref <SPEC-ID>`.
